# Troubleshooting Guide

Real errors encountered during deployment and their solutions.

---

## 1. Port 443 conflict: Caddy vs XRay

**Error:**
```
Failed to start: app/proxyman/inbound: failed to listen TCP on 443
transport/internet/tcp: failed to listen TCP on 0.0.0.0:443
listen tcp 0.0.0.0:443: bind: address already in use
```

**Cause:** Caddy already occupies port 443 for SSL termination.

**Fix:** Use port 2053 (or any other free port) for VLESS inbound in XRay config:
```json
{
  "inbounds": [{
    "port": 2053,
    ...
  }]
}
```

Also open the port on the edge node:
```bash
ufw allow 2053
```

## 2. Marzban node SSL certificate wrong file

**Error:**
```
[SSL: TLSV1_ALERT_UNKNOWN_CA] tlsv1 alert unknown ca (_ssl.c:2570)
```

**Cause:** Using the wrong certificate file. Many attempts with `cert.pem`, `server.pem`, `ca.pem` — all failed.

**Fix:** The correct file name is **`ssl_client_cert.pem`** and it must contain the certificate downloaded from Marzban panel → Node Settings → **"Download certificate"** button (NOT the eye icon, the download button).

```bash
# Correct path on edge node:
/var/lib/marzban-node/ssl_client_cert.pem
```

The docker-compose.yml must reference it as:
```yaml
environment:
  SSL_CLIENT_CERT_FILE: "/var/lib/marzban-node/ssl_client_cert.pem"
```

## 3. Marzban node uses REST not rpyc

**Error:**
```
(0, "('Connection aborted.', RemoteDisconnected('Remote end closed connection without response'))")
```

**Cause:** Node installed without REST protocol selected.

**Fix:** During node installation when prompted:
```
Do you want to use REST protocol? (Y/n): y  ← MUST answer y
```

Or manually set in docker-compose.yml:
```yaml
environment:
  SERVICE_PROTOCOL: "rest"
```

Then restart:
```bash
marzban-node restart
```

## 4. UFW enable fails with UnicodeDecodeError via Termius

**Error:**
```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd0 in position 0
```

**Cause:** UFW asks for confirmation `(y|n)?` and Termius sends non-ASCII input.

**Fix:** Always use force flag:
```bash
ufw --force enable
```

## 5. Nano editor corrupts config file

**Problem:** Pasting multi-line configs into nano via Termius resulted in corrupted files with mixed content.

**Fix:** Never use nano for config files. Always use heredoc:
```bash
cat > /etc/caddy/Caddyfile << 'EOF'
panel.1984vpn.com {
    reverse_proxy localhost:8000
}
EOF
```

## 6. Marzban node "already installed" blocks reinstall

**Error:**
```
Marzban-node is already installed at /opt/marzban-node
Do you want to override the previous installation? (y/n) y
Aborted installation
```

**Cause:** Previous broken installation left files but no docker-compose.yml.

**Fix:** Remove manually then reinstall:
```bash
rm -rf /opt/marzban-node
sudo bash -c "$(curl -sL https://github.com/Gozargah/Marzban-scripts/raw/master/marzban-node.sh)" @ install
```

## 7. Node connection "Unable to connect" — ports not open

**Error in Marzban logs:**
```
Unable to connect to "edge1-helsinki" node
```

**Cause:** Firewall blocking ports 62050/62051 on edge node.

**Fix:**
```bash
ufw --force enable
ufw allow 22
ufw allow 62050
ufw allow 62051
ufw allow 2053
ufw reload
```

## 8. Marzban panel not accessible externally

**Error:**
```
IMPORTANT! You're running Marzban without specifying UVICORN_SSL_CERTFILE and UVICORN_SSL_KEYFILE.
Marzban and subscription URLs will not be accessible externally.
```

**Cause:** Marzban needs a reverse proxy for external SSL access.

**Fix:** Use Caddy as reverse proxy (not direct SSL on Marzban):
```bash
apt install -y caddy

cat > /etc/caddy/Caddyfile << 'EOF'
panel.yourdomain.com {
    reverse_proxy localhost:8000
}
EOF

systemctl restart caddy
```

Caddy automatically obtains Let's Encrypt certificate.

## 9. Cloudflare proxy blocks SSL certificate issuance

**Problem:** `panel.yourdomain.com` shows Cloudflare animation instead of Marzban login.

**Cause:** Orange cloud (proxied) mode on Cloudflare intercepts HTTP-01 challenge from Let's Encrypt.

**Fix:** Temporarily set DNS record to **grey cloud (DNS only)** while Caddy obtains certificate. Once certificate is issued, can re-enable proxying.

Check certificate status:
```bash
journalctl -u caddy --no-pager | grep "tls.obtain"
# Should show: certificate obtained successfully
```

## 10. SSH key not found for Termius

**Problem:** Termius can't connect — key file not found.

**Fix:** Add Termius-generated key to server:
```bash
# From Mac Terminal (initial connection):
ssh root@SERVER_IP

# Add Termius public key:
echo "ssh-ed25519 YOUR_TERMIUS_PUBLIC_KEY Generated By Termius" >> ~/.ssh/authorized_keys
```

Get Termius public key from: Termius → Keychain → select key → copy Public key field.

## 11. Marzban node SSL — wrong certificate in ssl_client_cert.pem

**Error:**
```
[SSL: TLSV1_ALERT_UNKNOWN_CA] tlsv1 alert unknown ca
```

**After many attempts**, the working solution:

The certificate in `ssl_client_cert.pem` on the edge node must be **exactly** the certificate shown in Marzban panel → Node Settings → click the **eye icon** (Show Certificate) or **Download certificate** button.

This is NOT:
- The self-generated `client.pem` from `openssl req -x509...`  
- The `ssl_cert.pem` auto-generated by node installer
- Any CA certificate you generate manually

It IS:
- The certificate Marzban panel generates for itself (internal CA)
- Available via panel UI only

```bash
# On edge node, overwrite with correct content:
cat > /var/lib/marzban-node/ssl_client_cert.pem << 'EOF'
-----BEGIN CERTIFICATE-----
[paste certificate from panel here]
-----END CERTIFICATE-----
EOF

marzban-node restart
```

## Quick Diagnostic Commands

```bash
# Check Marzban status and logs
marzban status
marzban logs | tail -30

# Check node status
marzban-node status
marzban-node logs 2>&1 | tail -20

# Check what's listening on ports
ss -tlnp | grep -E "8000|62050|62051|2053|443|80"

# Check Caddy
systemctl status caddy
journalctl -u caddy --no-pager | tail -20

# Test node connectivity from master
curl -v --insecure https://EDGE_IP:62050

# Check firewall
ufw status
```
